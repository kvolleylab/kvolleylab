# 신인선수 드래프트 운영 명세 v1

상태: IMPLEMENTED / VERIFIED / READY FOR REVIEW. 운영 merge·배포는 승인 대기.

## 화면과 기존 기능 연결

- 경로: `v-league-draft.html?season=2026-27`. 프로 V-리그 메뉴는 V-리그 홈 → KOVO컵 → 드래프트 순서다.
- 기존 `draft-hub.html` 신청자 명단은 선수·팀 메뉴에 유지한다. 시즌 신청자 검색과 검증된 `player.html?id=KVL-P-…` 연결을 재사용한다.
- 기존 global sidebar, unified-nav, draft-hub의 밝은 배경·네이비·금색 및 팀 로고를 사용한다. 드래프트 스타일은 별도 범위에 둔다.
- 공개 화면은 조회용이다. 구슬 배분, 추첨 기록, 7열 결과표, 거래, 수정 이력, 출처를 구분한다.
- 미입력은 지명 대기다. 패스는 명시적으로 저장한다. 미확인 색상은 팀 색으로 추정하지 않는다.

## 지명권과 거래

지명권 ID는 `시즌:부문:라운드:원래팀`이다. 예: `2026-27:M:2:SFB`. 화면 열 번호와 추첨 순위는 ID에 포함하지 않는다. 추첨 전에도 거래·선수 기록이 이 ID에 연결된다.

- `original_team`: 변경되지 않는 원지명권 팀. 추첨 결과 및 라운드 규칙으로 순위를 계산한다.
- `current_team`: 원래 팀에 확정 거래를 순서대로 적용한 현재 보유팀. 저장된 값이 거래 이력 재계산과 다르면 전체 저장을 거부한다.
- `result.actual_team`: 지명·패스를 기록한 당시 실제 팀. 현재 보유팀 수정이나 선수의 현재 소속 변경으로 갱신되지 않는다. 공식 결과 정정 체크와 수정 사유가 있어야 명시적으로 바꿀 수 있다.

거래는 여러 `legs`를 한 트랜잭션으로 저장한다. 각 leg는 `pick_id/from/to`다. 맞교환은 양쪽 leg를 같은 거래에 넣는다. 전체 leg의 양도팀을 먼저 검사한 뒤 함께 반영한다. 28개 고유 지명권 및 각 권리의 단일 보유팀을 항상 유지한다. 팀별 권리 개수는 같을 필요가 없다.

`pending`은 확인 중으로 소유권에 영향을 주지 않는다. `confirmed`에는 거래일과 HTTPS 공식 출처가 필요하다. `cancelled`는 이력을 삭제하지 않는다. 재양도 뒤 선행 거래만 취소하면 보유팀 연결이 깨지므로 저장을 거부한다. 관리자가 후속 거래 동시 취소를 명시하면 관련 거래 전체를 취소 이력으로 남긴다. 취소 뒤에도 이미 지명된 선수·실제 지명팀은 보존한다.

각 변경은 인증된 GitHub 계정, 시각, 사유, 변경 전·후, revision을 audit에 기록한다. 거래가 원래 팀으로 돌아와도 확정 거래 이력과 배지는 남는다. 거래가 전부 취소되면 취소 목록과 수정 이력에서 확인할 수 있다.

## 추첨·결과·시즌 운영

- 처음 나온 팀만 새 추첨 순위를 받으며 중복 구슬은 나온 순서와 당시 색상을 유지한다. 6팀 입력만으로 남은 팀을 자동 확정하지 않는다.
- 결과표 열은 확정 추첨 순서, 그다음 미확정 팀의 배분 순서다. 미확정 순위를 숫자로 꾸미지 않는다. 추첨 정정은 열 위치만 바꾸며 지명권에 연결된 선수를 이동시키지 않는다.
- 1·3R 정순/2·4R 역순과 수련선수 역순은 제공된 양식 기준이다. 해당 시즌 공식 시행세칙은 아직 확인 중이다. 관리자는 라운드별 정순/역순/7팀 지정 순서를 설정하고 공식 확인 상태·출처를 저장할 수 있다.
- 수련선수는 정순/역순/지정/순서 없음, 팀당 제한 또는 제한 미확인, 설명을 관리한다. 각 팀의 entries 배열에 여러 선수를 고유 ID로 저장한다.
- 지명 대기/지명 완료/패스는 서로 다른 상태다. 완료 전환에는 7팀 추첨, 1R~4R와 수련선수의 지명 또는 패스가 모두 필요하다.
- 새로운 시즌은 `createSeason`으로 새 권리를 생성하고 공식 팀·확률·설명·출처를 별도 입력한다. index에 등록하기 전 state와 source의 시즌/부문을 대조한다. 전년도 추첨·결과·거래를 복사하지 않는다. 현재 선택 가능한 실제 자료는 2026-27 남자부뿐이다.

## 관리자와 영구 저장

기존 관리자 진입 화면에 드래프트 관리 링크를 추가했다. 기존 `admin-access.js`는 테스트 비밀번호와 localStorage 표시 플래그뿐이며 서버 인증 기능이 없다. 따라서 그 플래그만으로 신규 저장을 허용하지 않는다.

드래프트 관리자는 기존 `kvolleylab/kvolleylab` 저장소의 쓰기 권한이 있는 GitHub 계정으로 연결한다. 해당 저장소에 한정한 fine-grained 토큰의 Contents 읽기/쓰기 권한을 사용한다. 계정·push 권한을 확인한 뒤에도 실제 저장 권한은 GitHub가 매 PUT 요청에서 검증한다. 이 작업에서 새 계정·토큰·권한을 발급하지 않았다.

토큰은 탭의 private 메모리에만 보관한다. localStorage, URL, JSON, 로그, 저장소에는 넣지 않는다. 새로고침하면 다시 인증한다. 일반 방문자는 읽기만 가능하다.

저장 대상은 별도 **`data/draft-board` 브랜치**의 시즌 JSON이다. `main`은 페이지 소스와 사전 자료를 배포한다. 코드 PR을 merge해도 운영 입력 브랜치를 덮어쓰지 않는다. 공개 페이지는 최신 브랜치 데이터를 읽고 버전을 표시한다. 통신 실패 시 배포된 사전 자료를 표시하면서 최신 자료가 아님을 명시한다. 자동 폴링은 하지 않으며 GitHub 공개 API 요청 제한이 발생하면 새로고침으로 재확인한다.

한 번의 Contents PUT에 상태와 audit를 함께 저장한다. SHA 비교로 다른 관리자의 동시 수정을 덮어쓰지 않는다. 409·권한 오류·12초 시간초과·응답 유실 시 성공으로 표시하지 않고 입력을 유지한다. 최신 내용을 다시 읽기 전 추가 저장을 차단한다. 이 경우 재조회 결과를 확인한 후 필요한 변경만 다시 입력한다.

운영 전 계정 담당자가 자신의 토큰으로 인증·색상 등 확인된 자료 저장·새로고침을 한 번 확인해야 한다. 이 검수에서는 실제 브라우저에 사용자 토큰을 입력하지 않았다. 대신 실제 페이지 폼의 격리 검증과 인증된 Contents API의 실제 저장·브라우저 재조회를 각각 확인했다.

## 출처와 미확인 항목

2026-10-28 KOVO 공개 본문을 재대조했다. 공식 URL은 https://kovo.co.kr/news/kovo/press/157978 이며 발표일은 2026-10-22다. 10월 21일 언론 보도일과 구분한다. 개최 정보는 2026-10-28 14:30 KST, 서울 메이필드 호텔이다. 삼성화재35/OK30/한국전력20/KB8/우리카드4/현대캐피탈2/대한항공1의 배분을 참고 양식과 대조했다.

공식 구슬 색상·전체 추첨 로그·해당 시즌 시행세칙·라운드별 거래 공시/조건·최종 지명/패스 결과가 추가로 필요하다. 거래 정보가 없다는 이유로 확인된 거래 없음으로 표시하지 않는다. 가상 A→B 거래와 테스트 선수는 테스트에서만 생성하며 공개 시즌 자료에는 저장하지 않는다.

## 복구

코드는 이 기능 PR을 되돌려 복구한다. 기존 신청자·선수 원본은 수정하지 않았다. 실제 입력 브랜치는 별도로 보존한다. 데이터 오류는 관리자 정정 명령과 사유로 새 revision을 저장한다. 파일 손상은 GitHub의 마지막 정상 버전을 대조해 복구용 커밋을 만들고, 기존 커밋 이력은 삭제하거나 강제 덮어쓰지 않는다. 운영 merge·배포는 AGENTS.md의 승인 규칙을 따른다.
