## 실제 Google 변경과 재조회

남자 MASTER의 동일 문서 ID를 유지했다.

1. `선수ID_신원검수!L57`에 현재값 일치·효력일 미확정·자동 반영 보류라는 연결 검증 메모를 저장했다. 기존 ID·검수 처리일은 보존했다.
2. `KVL_자동반영이력` 탭 `710020128`에 22열 헤더를 만들었다. 첫 행 고정·기존 네이비 헤더 계열을 적용했다. 실제 적용 이력은 0행이다.
3. 두 변경을 native API로 재조회했고, 기존 현재등록표와 19열 변동 이력의 셀값은 변경 전후 동일했다.

공개 관측 영수증은 `data/player-updates/pilot_verification.json`이다. 이는 `MASTER_READBACK_VERIFIED` 적용 영수증이 아니며 writer에 입력할 수 없다. 원격 전체 행·비공개 메모·원본 API 응답은 공개 저장소에 넣지 않았다. 여자 MASTER는 조회만 했다.

Google 실제 화면 렌더링은 로그인 권한 차단으로 미확인이다. 변경 영역의 값·헤더·굵기·줄바꿈·고정행·grid 구조는 native API로 확인했다.

## 구현과 차단

새 writer는 정확한 기존 ID 한 명, 번호/포지션 한 사건, 명시적 효력일, 원문 revision, 최신 원격 셀·수식·검증·메모·보호 및 전용 저널을 확인한다. 단일 batch의 선수 셀과 이력 저장 후 전체 현재표와 저널을 재조회한다. source URL 텍스트와 실제 링크 대상도 함께 확인한다.

새 exporter는 해당 2026-27 현재 명단과 적용 근거 JSON만 허용한다. 같은 사건 반복은 추가 변경 0이며, 완료 대회·다른 선수·Player_ID·최초 등록 날짜/출처·기존 명단 Source_ID는 보존한다. 새 publisher는 선수 감시기간, 정확한 main SHA, Pages 성공 SHA 및 실제 공개 JSON 바이트를 검증한다.

실제 설정은 `enabled: false`, 승인 사건 0개다. 사유:

- 공시157018에 명시적 효력일이 없다.
- 선수 MASTER 권한 메타데이터에는 소유자만 있고 기존 GitHub 실행계정은 없다.
- 공유 설정을 위한 Google 로그인 단계는 자동 승인 검토에서 특정 계정 인증 권한 부족으로 거부됐다. 인증·권한을 우회하지 않았다.

현재값이 이미 맞기 때문에 번호를 되돌린 뒤 적용하는 인위적인 실험을 하지 않았다. 실제 선수값 변경0, 자동 적용 이력0, 홈페이지 명단 변경0이다.

- 원격 응답 손실 후 읽기 확인, 부분 읽기 실패 시 공개 export 금지, 동일 사건 반복0.

## 복구 및 다음 활성화

문제 발생 시 먼저 `pilot.json.enabled=false`를 유지한다. 구현 파일을 이전 commit으로 되돌려도 기존 경기 자동화와 원본 선수값은 유지된다. 연결 메모는 검수 이력이며 불필요하게 삭제하지 않는다. 비어 있는 전용 저널은 미사용 상태로 보존할 수 있다. 실제 적용 후의 복구는 단순 역쓰기 대신 원문·현재값·적용 이력 재대조로 진행한다.

다음 실제 적용에는 공식 효력일을 입증하는 적합한 후보, 기존 실행계정의 해당 MASTER 접근, 정확한 단일 `event_scope`, 원문 버전에 고정한 검토와 실제 실행·게시 영수증이 필요하다. 다른 선수로 범위를 넓히거나 날짜를 임의로 채워 활성화하지 않는다.
