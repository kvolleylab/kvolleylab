## 변경 계약

| 상황 | 새 처리 | 보호 조건 |
|---|---|---|
| 일시 timeout/5xx/429 | 공식 GET 최대2회 추가 시도 | 401/403·형식/신원/점수 오류는 맹목 재시도하지 않음. Retry-After가30초 초과면 조기 재시도 없이 보류 |
| 일정·문자중계 시작시각 차이 | 두 유효 HH:mm과 비교 결과 기록 | 시즌/단계/성별/경기번호/라운드/날짜/양팀 동일성 및 점수 검증 통과 필수 |

| 종료세트 득점 일부 미확인 | 검증된 승수/확인된 종료세트만 반영하고 누락 별도 보고 | 진행중 득점 추정·가짜 득점·전체 성공 표시 금지 |
| MASTER/인증/보안 오류 | 게시 전체 차단 | 보호 셀·수식·수동잠금·CAS·readback 및 승인 조건 유지 |
| 부분 후보 게시 | Pages SHA/남녀 JSON 검증 후 실패 상태와 알림 유지 | 게시 영수증 없는 후보/로컬 작성은 게시 성공이라고 하지 않음 |

공식 일정→공식 문자중계 보완 경로를 재사용한다. 새로운 비공식 점수 공급자나
브라우저 수동 점수 입력, 별도 스케줄러는 추가하지 않는다. 실패 부문을 다음
정상 수집에서 재검증한다. MASTER 쓰기·Git push·배포 전체를 무조건 재실행하지 않는다.

`--isolate-divisions`는 성별 전체126정규·3포스트시즌 경로·공식 순위를 각각 검증한다.
`--verify-candidate-ui`는 **실제 게시할 동일 후보**를 MASTER 쓰기 전에 DOM 검사한다.
정상 부문과 보류 부문을 합친 공개 파일 모두 보안 검사하며 보류 파일에 새 공식 검증
영수증을 부여하지 않는다. Pages는 계속 남녀 파일 전체의 정확한 바이트를 확인한다.
