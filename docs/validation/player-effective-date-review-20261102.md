## 결론과 작업 범위

Status: REVIEW COMPLETED / EXISTING EVENT PILOT BLOCKED / POLICY PROPOSAL ONLY.

확인한 남자부 후보 7건 모두 공시일만 제공한다. 그중 기존 ID가 연결된 후보는 3건이고, 현재 기준으로 승인 가능한 사건은 0건이다. 공시 본문과 2026–2027 운영요강에서는 별도의 효력일 근거를 확보하지 못했다. **별도 규약·선수등록규정 전체는 미확인**이므로 KOVO의 모든 규정에 근거가 없다고 단정하지 않는다.

이번 재대조에서는 선수 MASTER·신원 검수·적용 저널·선수 ID·공개 명단·운영 설정을 수정하지 않았다. 제안은 [현재값 확인·갱신 기준 초안](../proposals/player-current-value-policy-v1.md)에 분리했다.

## 3. 남자 MASTER와 실제 홈페이지 대조

기존 팀 계정의 연결로 [남자 선수 MASTER](https://docs.google.com/spreadsheets/d/1WD2odv51xNDx9BqRfAjkkLVu0p_DX2EX_GEbqR-G4og/edit)의 metadata와 `현재등록_공시기반!A3:K160`, `KVL_자동반영이력!A1:V200`을 읽었다. 비고 L열은 이번 조회에 포함하지 않았다. 아래 행 번호는 이 조회 당시 위치이며 다음 쓰기의 고정 주소로 사용하지 않는다.

공개 명단은 같은 작업에서 [실제 HTTPS roster](https://kvolleylab.com/data/competitions/v-league-men-2026-27/rosters.json)를 조회했다. 응답 SHA-256은 `84024e79877dd1938341e239602d943250bda8162a3981d76ff2db447656f0aa`로 main 파일과 일치했다. 이는 실제 배포 데이터의 검증이며 이번 재대조에서 페이지 화면을 새로 시각 검수했다는 의미는 아니다.

| 구단·선수 | 공식 변경 | MASTER 행·현재값 | 홈페이지 현재값 | MASTER·홈페이지 기존 ID |
|---|---|---|---|---|
| 우리카드 오재성 | 3→5 | 57행·5 | 5 | `KVL-P-001585` |
| 우리카드 이승원 | 62→6 | 44행·6 | 6 | `KVL-P-001548` |
| 우리카드 박진우 | 1→7 | 52행·7 | 7 | `KVL-P-001596` |
| 우리카드 이시몬 | 15→1 | 48행·1 | 1 | 공란 / null |
| 우리카드 박상우 | 38→3 | 43행·3 | 3 | 공란 / null |
| 우리카드 김영준 | 5→9 | 58행·9 | 9 | 공란 / null |
| 대한항공 김영태 | OH→MB | 14행·OH | MB | 공란 / null |

우리카드 6명의 MASTER J열과 홈페이지 `lastChangeSource`는 모두 공시 157018을 가리킨다. 기존 ID 3개는 canonical registry와 현시즌 명단의 이름·생년월일로 대조했다. 이름이 같은 대학 선수의 ID를 프로 선수에게 재사용하지 않았다.

김영태는 **MASTER OH / 홈페이지 MB 불일치**가 확인됐다. MASTER 출처는 최초 등록 공시 155577이고 홈페이지의 변경 출처는 157686이다. 기존 ID와 명시적 효력일이 없어 이번 파일럿의 대체 적용 대상으로 선택하지 않았다. 홈페이지가 맞다는 이유로 MASTER를 역으로 자동 수정하거나 새 ID를 만들지 않는다. 다음 신원 검수·MASTER 대조 대상에 남긴다.

`KVL_자동반영이력`은 metadata 기준 200행이며 전체 `A1:V200` 조회에서 헤더 1행만 반환됐다. **실제 적용 이력은 0행**이다. 이번 native 조회는 실제 GitHub 서비스계정의 선수 행 읽기나 쓰기 성공 증거를 대체하지 않는다.

## 4. 기존 한 건 파일럿의 정확한 상태

- 대상: 오재성 `KVL-P-001585` / 후보 `KVL-PC-1edba5fa875766ef2a4da329` / 공시 157018.
- 승인 사건 0건. `pilot.enabled=false`, `event_scope=null`, `BLOCKED_EFFECTIVE_DATE` 유지.
- 실행계정 metadata·헤더 접근: [Actions #26](https://github.com/kvolleylab/kvolleylab/actions/runs/41444659754)에서 이미 검증.
- 실제 선수값 쓰기·적용 이력 추가·쓰기 후 재조회·그 결과의 공개 배포: 수행하지 않음.
- 현재값이 이미 5번인 것은 실패 사유가 아니다. 진짜 효력일을 확보하면 기존 writer의 `verified_existing` 경로로 선수값 변경 0셀 / 실제 사건 이력 1행을 기록하고 재조회할 수 있다.
- 현재 날짜를 보완하려고 후보 JSON만 수정해도 실제 공시 재파싱과 맞지 않아 차단된다. 같은 공시의 명시적 날짜 조건을 조용히 변경하지 않는다.

## 5. 검수와 다음 결정

이번 변경은 검수 문서와 미승인 제안 문서뿐이다. 운영 코드·설정·데이터·Google 문서 수정이 없어 runtime/UI 테스트를 새로 수행하지 않았다. 실제 공식 응답, native 범위, 공개 명단, 코드의 날짜·ID 검사와 문서 표를 대조하고 링크·diff를 확인한다. 저장소 전체 CI 성공이나 자동 쓰기 활성화로 표시하지 않는다.

운영원칙 MASTER v17 11-3절과 현행 파일럿은 불명확한 효력일을 검수 대기로 둔다. 선택지는 다음 두 가지다.

1. 현재 기준 유지: 공식 효력일이 있는 적합한 번호·포지션 사건을 기다리고 후보 수집을 계속한다.
2. 제안 검토: 공식 자료에서 확인된 **현재 번호·포지션**과 **과거 효력일이 확정된 사건**을 분리한다. 효력일은 미확정으로 보존하고 확인 시각·출처를 별도 기록한다. 세부 제한·준비 조건은 연결된 초안에 명시했다.

이번 문서의 작성·Draft PR 제출은 두 번째 운영 기준의 승인이나 배포가 아니다. 문서만 되돌리면 운영 동작에 영향이 없으며 기존 v17과 비활성 파일럿은 그대로 유지된다.
