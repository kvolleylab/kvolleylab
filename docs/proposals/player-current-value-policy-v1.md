# 선수 현재값 확인·갱신 기준 — 검토안 v1

Status: PROPOSED / NOT APPROVED / NOT IMPLEMENTED / NOT ACTIVE.

근거: [2026-11-02 공식 날짜·MASTER·홈페이지 재대조](../validation/player-effective-date-review-20261102.md). 현재 운영원칙 v17 11-3절이나 실제 파일럿 설정을 변경하지 않은 제안이다. 문서 승인을 실제 자동 쓰기 성공으로 표시하지 않는다.

## 해결하려는 문제

공식 배번·포지션 변경 공시가 변경 내용과 공시일만 제공하면 현재 파일럿은 실제 효력일을 확인할 수 없어 멈춘다. 현재 명단의 값이 맞는지 확인하는 작업과, 과거 어느 날부터 변경이 효력을 가졌는지 확정하는 작업을 구분할 필요가 있다.

**제안:** 기존 ID가 검수된 선수의 현재 번호·포지션은 공식 현재명단과 변경 공시를 대조하여 확인할 수 있게 한다. 과거 효력일이 없는 경우 그 날짜는 미확정으로 보존한다. 현재 명단을 수정하는 경우도 허용 범위·원문 버전·실제 쓰기 후 재조회가 있는 별도 기록으로 남기며, 기존 효력일 확정 사건으로 변환하지 않는다.

## 1. 날짜와 기록 유형

| 항목 | 의미 | 허용하지 않는 대체 |
|---|---|---|
| `published_at` | 출처가 제공한 공시 게시 시각 | 효력일로 재사용하지 않음 |
| `source_as_of` | 공식 현재명단이 명시한 기준일 | 없으면 관측 시각으로 채우지 않음 |
| `observed_at` | 공식 자료 조회·대조를 완료한 실제 시각 | 파일 생성일·추정 변경일로 사용하지 않음 |
| `effective_date` | 공식 근거로 확정한 실제 효력일 | 미확인 시 null 유지 |
| `applied_at` | 실제 MASTER 저장과 재조회가 완료된 시각 | 역사적 등록일로 사용하지 않음 |

별도 `record_type: official_current_state`를 사용한다. 원문·신원·현재값 확인 기록, 실제 MASTER 변경 기록, 역사적 효력일 확정 이벤트를 구분한다. `docs/PLAYER_OBSERVATION_SCHEMA_v1.md`의 비공개 스카우팅 메모와도 다른 자료다. 기존 `event_id`, 적용 이력 상태, `MASTER_READBACK_VERIFIED`를 새 기록에 그대로 재사용하지 않는다.

## 2. 적용 전 필수 확인

1. 기존 Player_ID가 canonical registry와 대상 MASTER에서 정확히 한 선수에게 연결되어야 한다. 이름만으로 ID를 채우거나 새로 만들지 않는다.
2. 공식 현재명단의 시즌·성별·팀·선수·최신 적용 범위를 확인한다. 최근에 내려받은 문서라는 이유만으로 현재 명단이라고 판단하지 않는다.
3. 공식 현재명단과 해당 변경 공시가 번호·포지션에 일치해야 한다. 공시·명단 각각의 원문 ID, URL, 버전/해시, 조회 시각, 원문 위치를 남긴다.
4. 더 최근 정정·소속 변경, 미래 적용 명시, 조회 시각보다 미래인 게시 시각, 재조회 사이 원문 버전 변경, 출처 간 충돌, 불명확한 최신성, 조회 실패는 검수 대기로 둔다. 기존 KVL 홈페이지와 MASTER의 상호 일치만으로 공식 근거를 대체하지 않는다.
5. 변경을 허용할 때는 정확한 한 선수·필드·변경 전후 값·출처 버전에 검토를 고정한다. 수식·보호·수동잠금·새 사용자 수정·중복 기록 검사와 실제 재조회가 필요하다.

기록에는 범위, 원문 근거 2개, 신원 검토 근거, 확인값, 해당하는 날짜·시각(미확인 효력일·기준일은 null), 검토 역할·시각, 실행 식별자, MASTER 확인값·시각·일치 결과가 필요하다. 공개 저장소에는 허용된 정제 필드만 넣고 원격 전체 행·비공개 메모는 보존하지 않는다.

## 3. 첫 적용 제안은 한 명의 현재값 확인

대상은 기존 파일럿의 오재성 `KVL-P-001585` / 우리카드 / 2026–27 남자부 / 등번호 5다. 기존 변경 공시 157018과 ID·MASTER·홈페이지의 5번 일치는 재확인했다. **독립적인 공식 현재명단의 최신성·값 대조는 아직 완료하지 않았다.** 따라서 정책 결정만으로 즉시 활성화할 수 있는 상태는 아니다.

첫 적용은 공식 현재명단을 추가 검증한 뒤, 선수값이 이미 같은 경우에 한정하여 별도 현재값 확인 기록을 저장하고 다시 읽는 것으로 제안한다. 결과는 선수값 변경 0셀, 확인 기록 저장·재조회 성공 여부, 과거 효력일 미확정으로 보고한다. 실제 선수 셀을 바꾼 writer 성공이나 기존 사건 파일럿 완료로 표시하지 않는다.

**값이 다르면 이 첫 확인 경로에서는 수정하지 않고 검수 대기로 둔다.** 값이 다른 번호·포지션을 실제로 갱신하는 확장은 그 대상·원문·수정 계획을 따로 검토한다. 이 문서의 승인만으로 322개 후보나 남녀 전체 선수를 자동 반영하지 않는다.

## 4. 유지할 경계

- 등록·이적·임대·복귀·해지·은퇴 및 현재 소속·등록 상태는 기존 변경 사건 기준을 유지한다.
- 대회 당시 명단, 과거 시점 재구성, 최초 등록일은 현재값 확인 기록으로 수정하지 않는다.
- 김영태의 MASTER/홈페이지 포지션 차이는 기존 ID 연결 검수부터 별도로 해결한다.
- 같은 실행 재시도는 확인 기록을 중복 생성하지 않는다. 원문 정정은 새 검토가 필요하다.
- 기존 사건 경로의 `BLOCKED_EFFECTIVE_DATE`를 해제하거나 승인 이벤트를 생성하는 방식으로 구현하지 않는다.
- 공시 수집·기사 발견·경기 결과 자동화의 운영 기간과 기존 권한 범위를 이 제안으로 확대하지 않는다.

## 5. 운영원칙에 추가할 문구 초안

> 현재 번호·포지션의 확인은 과거 효력일이 확정된 변경 사건과 구분하여 기록할 수 있다. 기존 Player_ID와 공식 현재명단·변경 공시의 일치 및 최신성을 검수하고, 공식 효력일을 확인할 수 없으면 미확정으로 보존한다. 공시일·확인일·MASTER 반영일을 효력일이나 최초 등록일로 대신 사용하지 않는다. 이 확인 기록은 등록·이적·해지 판단과 과거 대회 명단 재구성의 근거가 될 수 없다. 실제 현재값 수정은 별도 검토 범위·원문 버전·허용 셀·쓰기 후 재조회가 확인된 경우에만 수행한다.

이 문구를 채택하기 전에는 기존 `KVL_운영원칙_MASTER_v17` 11-3절이 유효하다. 채택 시에는 해당 Google MASTER의 원칙 변경 절차에 따라 변경 사유·영향 범위·버전을 기록하고, 구현 문서와 활성화 기준을 같은 의미로 맞춘다.

## 6. 구현·검증 준비 목록

아래는 필요한 후속 작업이며 완료된 작업 목록이 아니다.

| 준비 항목 | 통과 조건 |
|---|---|
| 공식 현재명단 | 정확한 시즌·구단·기존 선수 신원·번호와 자료 최신성 검증 |
| 별도 schema·저장 위치 | 원본 사건·개인 관찰 메모와 분리, nullable 효력일, 출처·확인일 보존 |
| 읽기·저장·재조회 | 정확한 대상, 단일 확인 기록, 같은 실행 중복 0, 실패를 성공으로 표시하지 않음 |
| 회귀 | 명시 효력일 없는 기존 사건 차단 유지, 원문 정정·ID 공란·출처 충돌·값 불일치 차단 |
| 공개 결과 | 확인일 표시와 효력일 미확정을 분리, 기존 등록일·과거 로스터 보존 |
| 실제 실행 | 기존 계정으로 실행한 영수증·읽기 재확인·공개 결과를 각각 검증 |

결정할 내용은 **현재 기준을 유지할지, 위처럼 현재값 확인 기록을 별도로 도입할지**다. 승인되지 않은 상태에서 코드·Google 운영원칙·자동 실행 설정을 변경하지 않는다.
