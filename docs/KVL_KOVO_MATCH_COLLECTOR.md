# K-Volley Lab · KOVO Match Data Collector v0.1 (read-only pilot)

## Verified access boundary (2026-10-17)
- DB BANK entrance: https://dbbank.kovo.co.kr/ redirects to a login page. It states the site is intended for clubs, broadcasters and press.
- Some individual result URLs are independently readable through public web indexing. Example:
  https://dbbank.kovo.co.kr/game/11110_pop_result.asp?PID=gUjNxoTMwIjOyIDM
  On 2026-01-22, 한국도로공사 beat IBK기업은행 3-1 (22-25, 25-22, 25-21, 25-21); match no. 165, attendance 2313.
- A page opened through public web indexing does NOT demonstrate that unauthenticated automated requests from GitHub Actions are authorized or will succeed. A real network probe must be checked in Actions. The local sandbox cannot access the origin because DNS/network access is disabled.
- The test URL above is 2025-26 V-League historical data, NOT a 2026 KOVO Cup match. Opaque PID is supplied manually and must never be fabricated.
- This pilot does not bypass login, guess IDs, use cookies, hidden sessions, authentication, CAPTCHA, or request unpublished endpoints. Stop on 401/403/429, login response, redirect to login, or unexpected HTML.

## Code and workflow
- Read-only fetch+parse: scripts/kovo_match_collector.py
- Synthetic offline tests: tests/test_kovo_match_collector.py
- Manually verified public pilot URL plus matching expectations: data/kovo/match-collector/pilot_sources.json
- Action: .github/workflows/kovo-match-collector-pilot.yml
- Local: python -m unittest discover -s tests -p test_kovo_match_collector.py -v
- Manual run: python scripts/kovo_match_collector.py --manifest data/kovo/match-collector/pilot_sources.json --output data/kovo/match-collector/pilot_results.json
- GitHub: Actions > KOVO Match Collector Pilot > Run workflow, inspect live-probe step and uploaded kovo-match-collector-pilot artifact.

## Schema / meaning
- Status parsed_review_required: date, teams, 3-2/3-1/3-0 final sets, per-set points and official game number were extracted from one openly readable match page AND optional manually provided expected facts agreed.
- Record includes original source URL, retrieval UTC time, content SHA-256, venue and attendance if present.
- No unverified source data are written as league results. No output file is modified until all match records have passed validation.
- Status player_stats_status=not_collected: while DB BANK pages show player stats, their raw HTML structure has not yet been verified against real fixtures. Do not claim individual stat extraction.
- No automatic match-ID discovery, live ticker feed, scheduled update, or cross-site publication is implemented. A match URL list is an explicit limited input, not generated by ID guessing.
- Action uploads a diagnostic artifact only. It never commits results to main, modifies competition JSON, homepage, Google Drive MASTER, or existing notices collector.

## Safety and diagnostics
- HTTPS only, exact DB BANK hostname and match-path allowlist. Reject unknown query keys, user-info, custom ports, invalid PID/PSET.
- Strict 2 MB response maximum; 18-second timeout; 1s minimum delay; at most 20 hand-listed matches/run.
- Redirect to login is treated as failure. Never log or store full HTML, login payload, credentials or cookies.
- Each source's role, year and league must be documented so 2025-26 regular-season results are not merged into 2026 Cup.
- Review JSON artifacts for provenance; do not publish by default.
