# K-Volley Lab 모바일 대회 페이지 기본 템플릿 v2

## 목적

이 문서는 K-Volley Lab의 **모바일 대회 상세페이지 공통 기준**이다.
특정 실제 대회 페이지를 기준본으로 지정하지 않는다. 실제 대회 페이지는 구현 사례일 뿐이며, 공통 템플릿 자체는 별도 파일과 이 문서에서 관리한다.

## Source of Truth

- 모바일 템플릿 규격: `docs/KVL_MOBILE_COMPETITION_TEMPLATE_V2.md`
- 신규 대회 HTML 시작점: `templates/competition-page-v1.html`
- 공통 대회 UI: `assets/css/kvl-competition-template-v1.css`
- 공통 대회 렌더러: `assets/js/kvl-competition-template-v1.js`
- 공통 데이터 예시: `data/competitions/_template/competition-v1.template.json`
- 모바일 공통 보조 CSS: `assets/css/kvl-mobile-competition-template-v1.css`

실제 특정 대회 HTML 파일은 Source of Truth가 아니다.

## 1. 화면 기준

- 기본 검수 폭: 390px.
- PC 화면을 단순 축소하지 않고 모바일용 정보 밀도로 재구성한다.
- 특별한 사유가 없는 한 가로 스크롤을 사용하지 않는다.
- 표의 모든 핵심 열을 한 화면에 넣을 수 없는 경우에만 해당 표 영역에 한해 가로 스크롤을 허용한다.
- 모바일 전용 수정은 PC 레이아웃에 영향을 주지 않도록 media query와 범위가 명확한 selector로 제한한다.

## 2. 상단 대회 메뉴

기본 6개 메뉴:
`한눈에보기 / 경기일정 / 조별순위 / 최종순위 / 참가국·참가팀 / 공식자료`

- 1행 3개 + 2행 3개.
- 버튼 폭·높이·글씨크기를 동일하게 유지.
- 메뉴 자체의 가로 스크롤은 금지.
- 선수명단 등 추가 기능이 있는 대회는 공통 정보 순서를 해치지 않는 범위에서 기능을 확장한다.

## 3. 한눈에 보기

- 핵심 KPI 카드는 기본 2×2.
- KPI는 관련 상세 페이지 또는 해당 섹션으로 이동할 수 있게 한다.
- 대회 기간, 개최지, 경기장, 참가 규모, 현재 상태를 첫 화면에서 빠르게 확인할 수 있어야 한다.
- 모바일 메인 카드에서 `날짜 / 장소 / 경기장`이 자연스럽게 한 줄에 담기지 않으면 억지로 줄바꿈하지 않고 각각 1줄씩 총 3줄로 분리한다.
- 한눈에 보기의 개최지는 작은 뱃지가 아니라 KPI 영역과 같은 크기의 `장소` 카드로 제공한다. `장소` 라벨 아래에 `국가/도시 + 경기장` 전체 정보를 표시하고, 모바일에서는 2열 KPI 아래 전체 폭을 사용한다.
- 대회 종료 후에는 우승팀·최종 상태 등 핵심 결과를 짧게 표시할 수 있다.

## 4. 대회 월간 달력

- 7열 월간 달력을 모바일 한 화면 폭에 맞춘다.
- 가로 스크롤 금지.
- 경기 있는 날짜는 경기 수 또는 간단한 경기 존재 표시를 제공한다.
- 390px 기준 달력 안의 경기시간은 보조정보로 취급하며 기본 `8px` 수준으로 유지해 날짜·경기수보다 시각적 우선순위가 높아지지 않게 한다.
- 날짜 선택 시 경기일정 페이지의 해당 날짜 묶음으로 이동할 수 있게 한다.
- 다른 날짜 경기 묶음은 유지한다.

## 5. 경기일정·결과

모바일 기본 정보 순서:
1. 경기시간
2. 양 팀 국기 + 팀명·국가명 + 세트스코어
3. 세트별 스코어
4. 단계 · 조 · 경기장 등 보조정보

- 양 팀은 중앙 스코어를 기준으로 좌우 대칭 정렬한다.
- 국기·팀 로고의 크기와 비율은 동일하게 유지한다.
- 세트별 스코어는 세트 번호 없이 숫자 중심의 짧은 표기를 기본으로 한다.
- 단계 필터는 가능한 한 한 줄에 표시한다.
- 조별리그 하위 조 선택은 단계 필터와 분리한다.
- 팀명/국가명은 가능한 한 한 줄을 유지한다.

## 6. 조별순위·예선 종합순위

- 조별순위는 모바일에서도 팀명과 핵심 성적을 빠르게 확인할 수 있어야 한다.
- 예선 종합순위가 필요한 대회는 참가팀 전체를 표시하는 것을 기본으로 한다.
- 열이 많은 종합순위 표는 해당 표 영역에 한해 가로 스크롤을 허용할 수 있다.
- 처음 보이는 영역에는 `순위 / 국기·로고 / 국가·팀 / 결과 또는 상태` 등 핵심 식별정보를 우선 배치한다.
- 세부 통계는 오른쪽으로 스크롤해 확인하도록 배치할 수 있다.
- 헤더와 본문 값은 같은 열 중심선에 맞춰 정렬한다.
- 조별리그 진행 중인 예선 종합순위는 `종합순위 / 국기·로고 / 국가·팀 / 조순위 / 세부통계...` 순서를 기본으로 한다.
- 조별리그가 모두 끝나면 같은 표가 자동으로 `종합순위 / 국기·로고 / 국가·팀 / 결과 / 세부통계... / 조순위` 순서로 전환되도록 할 수 있다. 완료 여부는 데이터의 조별리그 전체 경기 완료 상태로 판단한다.

## 7. 최종순위·결선

- 최종 1~4위 카드는 기본적으로 한 줄 4개를 우선한다.
- 국기·로고 비율과 크기를 통일한다.
- 최종순위 아래에 결선 토너먼트를 연결할 수 있다.
- 결선 경기 결과는 `국기/로고 + 팀명 + 스코어 + 팀명 + 국기/로고` 형태의 고밀도 한 줄 구성을 우선 검토한다.
- 대회 구조상 정보 손실이 생기면 세로형 카드 사용을 허용한다.
- 아직 대진이 확정되지 않은 결선 카드에서 `예선 종합 n위`, `현재 예상` 같은 보조문구는 축소를 우선하지 말고 팀/시드 본문 약 12~13px, 보조문구 약 9~10px 수준의 가독성을 우선한다.

## 8. 참가국·참가팀

- 기본 2열 카드 배치.
- 국기·로고 / 한글명 / 필요 시 영문명 / 조·부문 정보를 표시한다.
- 카드 높이와 이미지 크기를 통일한다.

## 9. 색상과 테마

- 레이아웃 규칙과 색상 규칙을 분리한다.
- 성별·국내/국제·대회별 테마색은 CSS 변수 또는 별도 테마 레이어에서 처리한다.
- 특정 실제 대회의 색상을 공통 템플릿에 하드코딩하지 않는다.
- 우승·진출·탈락 등 상태 배지는 의미가 명확해야 하며, 페이지별 예외색은 공통 규칙으로 자동 승격하지 않는다.

## 10. 구현·수정 원칙

- 특정 대회에서 만든 임시 CSS/JS를 그대로 공통 템플릿에 복사하지 않는다.
- 두 개 이상의 대회에서 반복적으로 필요한 구조인지 확인한 뒤 공통 템플릿으로 승격한다.
- 공통화는 HTML runtime patch보다 정적 HTML·공통 CSS·공통 renderer를 우선한다.
- 레이아웃 수정을 위해 DOM MutationObserver를 새로 추가하지 않는다.
- 기존 정상 페이지를 일괄 변환하지 않는다. 필요한 시점에 점진적으로 공통 템플릿을 적용한다.

## 11. 새 대회 모바일 제작 순서

1. 최신 GitHub `main` 확인.
2. Drive 원본·MASTER 위치 확인.
3. `templates/competition-page-v1.html`을 시작점으로 사용.
4. `_template/competition-v1.template.json`을 새 대회 데이터 구조로 복사.
5. 공통 UI/renderer를 우선 사용.
6. 대회 고유 규정만 별도 runtime/data에 추가.
7. 390px 모바일 검수.
8. PC 회귀 여부 확인.
9. 반복 개선사항이 공통 요소인지 판단 후 템플릿에 승격.
